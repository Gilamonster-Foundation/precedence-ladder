# `formal/` — the Lean layer

A machine-checked model of `src/lib.rs::Ladder::resolve`. Self-contained: no
Mathlib, so it builds from a bare Lean toolchain (pinned in `lean-toolchain`).

```sh
cd formal
lake build     # checks every theorem; exit 0 iff all proofs go through
```

Or from the repo root: `just lean` (the proofs) and `just no-sorry` (the gate
below). CI runs both in `.github/workflows/formal.yml`.

## Read this before citing a theorem

**Nothing in Lean reads `src/lib.rs`.** `Precedence/Basic.lean` is a
*transliteration* of `resolve` — four branches in source order — and every
theorem in it is a statement about that transliteration. Two of the four are
true *by construction of the model*, which means they establish that the model
is consistent, not that the Rust refines it.

What ties the two together is the **golden vectors**: `Precedence/Vectors.lean`
is generated by `just gen-vectors` from verdicts the real `Ladder::resolve`
produced, and `lake build` re-derives every one of them with `decide`. A
transliteration error is a red build. That file, and the drift check that keeps
it fresh (`scripts/check-vectors.sh`, in CI and the push hook), are the bridge —
not the theorems.

| Theorem | Status | What it establishes | What it does **not** establish |
|---|---|---|---|
| `resolve_hatch` | **spec** (model-internal) | A reserved trigger, while work runs, escapes — for *every* ladder, with no hypothesis on `rungs`. Discharged by `simp` on this file's own `resolve`, because the hatch branch precedes the rung scan *in this definition*. | That Rust's `resolve` has that branch order. Nothing here reads the Rust. The evidence for the Rust is `tests/truth_table.rs` (the invariant checked at all 192 grid points, plus a hostile table) and the `rogue` vector grid below. |
| `describe_agrees` | **spec** (`rfl`) | `describe` is `resolve`'s label, so an affordance cannot advertise what `resolve` will not do. Definitional in Rust too. | That any consumer renders its hint *from* `describe`. That is a consumer-side test. |
| `first_match_inv` | **proven** | A `claimed` verdict names a rung that is in the table, owns the trigger, is live — and *every rung ahead of it declined*; and the hatch branch did not fire. The "everything earlier declined" half needs the induction in `firstClaim_inv`; it is not `simp` on the definition. | Again: about the model's `resolve`. Its Rust twin is `the_whole_input_space`, whose per-claimant win counts (32/16/8/4/2) are this lemma's numerical shadow. |
| `declining_rung_is_transparent` | **proven** | **The registration-safety theorem.** A rung that does not own the trigger, or whose claimant is not live, can be inserted at *any* index without changing any verdict — over hostile tables, with no well-formedness hypothesis. This is what licenses a new claimant registering a rung instead of standing up its own input loop. | That a registered claimant *declines when it should*. That is the consumer's claim accessor, guarded by a consumer-side conformance test. |
| `demo_vectors_agree`, `rogue_vectors_agree` | **proven** (generated) | The model reproduces all 704 verdicts the shipped `resolve` produced. This is the transliteration check, and on the `rogue` grid it is the escape-hatch invariant witnessed against real Rust output rather than proved by construction. | Anything about inputs outside the two grids. The grids are exhaustive over their own claimant powersets and trigger sets, and that is all. |
| `demo_verdict_distribution`, `rogue_verdict_distribution` | **proven** (generated) | The exact `(claimed, escape, unbound)` counts. `vectors_agree` alone would be satisfied by a grid that had collapsed to one verdict kind — both sides would agree on the collapse. | — |
| `demo_order_is_load_bearing`, `rogue_order_is_load_bearing` | **proven** (generated) | The same inputs against the same rungs *reversed* give a different answer vector, so rung ORDER is observable. Without it a ladder is a set and the crate need not exist. Rust twin: `reversing_the_rungs_inverts_the_distribution`. | — |

Two model gaps, stated rather than implied:

- Rust uses `BTreeSet` for `reserved`, `triggers`, `fallthrough` and the claim
  set; the model uses `List`. `resolve` only asks those for **membership**, so
  the verdict is identical — but a property depending on sortedness or
  deduplication would not transfer, and none is proven.
- **Non-emptiness of the hatch is not modelled.** In Rust it is unrepresentable
  (`Hatch::new` takes a first element plus a rest, so an empty reserved set has
  no spelling); a Lean structure cannot express "there is no other constructor".
  `resolve_hatch` is therefore vacuous over a hypothetical empty hatch. The Rust
  guarantee is `Hatch::new`'s signature and `LadderError::EmptyReserved`.

### What was cut, and why

The plan for this slice listed more theorems than are here. Anything that
constrained nothing was deleted rather than kept for the count:

- `resolve_total` — functionhood dressed as a theorem. Lean definitions are
  total; it proves the type checker ran.
- `prefix_invariance` — implied by `first_match_inv`, cited by nothing.
- `nonsilence` — a `simp` weakening of `resolve_hatch`.
- any `wf`-hypothesis variant of the hatch theorem — **false** under hatch-first
  resolution, because a rung is unreachable on the reserved branch. `decide`
  would fail and `lake build` would go red, which is the correct outcome.
- any escalation-tier law — the crate has no tiers, on purpose.

## The `sorry` gate is real, and here is the proof

`scripts/check-lean-proofs.sh` greps this tree for `sorry` and `native_decide`.
It exists because **`lake build` exits 0 on a `sorry`** — verified, not assumed:

```
$ printf 'theorem seeded_stub : 1 = 1 := by sorry\n' >> Precedence/Basic.lean
$ lake build >/dev/null 2>&1; echo $?
0                      # green, with an unproven theorem in the tree
$ ../scripts/check-lean-proofs.sh; echo $?
Precedence/Basic.lean:293: theorem seeded_stub : 1 = 1 := by sorry
1                      # the gate catches it
```

`native_decide` is refused on the same grounds: it discharges a goal by running
compiled code, adding `Lean.ofReduceBool` to the trusted base. Every `decide`
here is a kernel reduction — `#print axioms` on the generated theorems shows
`propext` at most, and `verdict_distribution` / `order_is_load_bearing` show
none at all. (`set_option maxRecDepth` in the generated file raises an
elaborator budget, not a trust boundary.)

The scan carries a positive read assertion: it fails if it finds fewer than two
`.lean` files — the hand-written root module and the model — because an absence
check fails *open*, and anything that shrinks the scanned text makes it more
likely to pass. The floor is the hand-written tree, not today's file count: a
*generated* module going missing is `lake build`'s job (the import fails) and
`check-vectors.sh`'s (the diff), so pinning it higher would make the gate
brittle without making it stricter.

## Mutations these gates were checked on

Each was applied, observed, and reverted. A gate nobody has watched fail is a
gate nobody knows works.

| # | Mutation | Result |
|---|---|---|
| 1 | seed `theorem seeded_stub : 1 = 1 := by sorry` | `lake build` **exit 0** (the gap); `check-lean-proofs.sh` **exit 1** |
| 2 | seed a `native_decide` proof | `check-lean-proofs.sh` **exit 1** |
| 3 | flip one `expected` verdict in `Precedence/Vectors.lean` | `lake build` **exit 1**: "`decide` proved that the proposition … is false" |
| 4 | hand-edit a claimant name in `spec/vectors/ladder.json` | `check-vectors.sh` **exit 1** with the diff |
| 5 | demote the hatch branch below the rung scan in `src/lib.rs` | `check-vectors.sh` **exit 1**, 262 changed lines including `content_id`; `cargo test` red on 2 tests |
| 6 | drop the `is_live` conjunct from the model's `rungMatches` | **all four `Basic.lean` theorems still compile**; all four vector theorems go red |

Mutation 6 is the one worth remembering: it is the case the theorems cannot
catch and the vectors can. Mutation 5 is why there are two grids — against the
`demo` table alone it produced **zero** drift, because no rung of that table
claims a reserved trigger, so the grid could not tell hatch-first from
hatch-last. The `rogue` grid exists to make resolution order observable.

## Layout

| File | |
|---|---|
| `lakefile.toml` | `[[lean_lib]] Precedence` **and** `defaultTargets = ["Precedence"]`. A library absent from `defaultTargets` is not built by `lake build`, so its theorems are never checked and CI is green having compiled nothing. |
| `Precedence.lean` | root module; imports only |
| `Precedence/Basic.lean` | the model and its four theorems, hand-written |
| `Precedence/Vectors.lean` | **generated** by `just gen-vectors`; never hand-edit |

## What is not here

**No TLA+.** A pure function has no temporal behaviour, and a temporal spec
beside one would constrain nothing. The sequencing this crate's consumers care
about — which input context owns the keyboard, and whether every context has a
hatch — lives in the *consumer*, and so does its TLA+ model.
